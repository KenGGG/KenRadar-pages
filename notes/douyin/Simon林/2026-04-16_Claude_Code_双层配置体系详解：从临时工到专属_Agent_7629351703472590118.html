一、内容简述

（一）一句话结论

一句话结论 · 内容来源的摘要 本文介绍了 Claude Code 的两层配置架构（系统层级与项目层级），共涉及七个核心文件。通过合理配置，可将 Claude Code 打造为具备全局工作流约束和项目专属记忆的独立 AI Agent，实现‘配一次，管所有’的高效开发体验，避免重复交代背景与规则。

（二）核心内容

  1. 配置架构概览 Claude Code 配置分为系统层级（全局生效）和项目层级（单项目独立）。系统层级包含3个文件，对所有项目共享；项目层级包含4个文件，仅在当前项目生效。

  2. 系统层级配置详解 系统层级包含 .claude.md（定义身份与工作流）、.claude/settings.json（权限钩子与环境变量）以及 .claude/rules.md（代码规范与安全规则）。其中 settings.json 可配置工具权限 bypass、环境变量等过渡系统。

  3. 项目层级配置详解 项目层级包含 .md（项目背景与工作方式）、memory.md（项目记忆，系统层级无此功能）、commands（命令集）及 settings（项目专属设置）。该层级让 AI 记住特定项目的上下文、风格及历史题材。

  4. 应用场景与优势 通过配置，Claude Code 可针对不同项目（如亚马逊选品、短视频创作）自动加载专属规则与记忆。例如，在短视频项目中，AI 能自动继承之前的题材与风格，无需每次从头介绍，显著提升效率。

2. 系统层级文件介绍

第一个是 .claude.md，它是告诉 Claude 你是谁、是怎么工作的。然后是 .claude/settings.json，它是一个权限钩子跟环境变量。第三个是 .claude/rules.md，它是一个代码编码的规范和安全的规则。

3. 项目层级文件介绍

下面的是项目层级，它是四个东西，只是在当前的项目生效的。它也有一个 .md，然后这个是交代项目背景跟工作方式。还有 memory.md，系统级是没有 memory 的，只有项目层级有，所以这个是项目的记忆。然后这个是 commands，还有 settings，这是项目专属的一些设置。

4. 配置后的效果与案例

我们再设定完系统层级之后，就上面这个橙色标签了，然后就到项目层级了。系统层级是每次都是生效的。然后针对每一个项目呢，我们就可以设定不同的一些规则。就比如说第一个是亚马逊的选品，那我的 .claude.md 写的内容肯定是一些我这个选品的方向啊、我做什么呀、你要注意什么、以这些选品的策略之类的。然后 memory.md 呢，他就会记得你一些你自己的产品之类的，以及一些选品的规则策略。

还有这个就是哦我想给大家重点分享的就是你的项目的 agent，可以通过 Claude Code 来实现。当你配置好了一次之后，你每个项目都是拥有 Claude Code 这样的大脑。然后这样聪明的一些编排，这么严谨的、高效的一个助手的一个独立的 AI 助理，他能记得你是谁，然后他有项目记忆，然后他还有规则约束，而且他是随时开工的。

还包括第二个，就是我这关键的节点要确认。然后第三个就是最小的编辑面，就是你自己的一些工作方式跟风格跟你的需求都可以列进去。而且呢他就不需要每次介绍自己，然后还有统一的工作流程，还有记忆规则。就是其实你还可以再往里加很多东西，就包括你自己有几台设备，你像我就有两台设备。然后他们俩经常是要互联的，就是我通过我的主电脑去操作另外一台电脑。那其实我每次我不用教它了，我直接让他去操作就好，我只要提那个那个设备，它就会去连接 SSH 过去去连接去操作的。所以很多东西都可以放进去，就是你就很方便。
